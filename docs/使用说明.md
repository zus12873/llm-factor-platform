## 一、这个平台解决什么问题

研究员有一个想法：「ROE 高的股票未来收益更好」。从这句话到一个能跑、能复现、
能被别人检查的因子，中间有一串容易出错的步骤：

- 「ROE」是 ROE_TTM、ROE_摊薄、还是扣非 ROE？
- 它在 Wind 的哪张表哪个字段？单位是百分数还是比值？
- 财报数据什么时候才公开？用报告期还是公告日？
- T 日收盘算出的因子，能在 T 日交易吗？
- 三个月后重跑，数字不一样了，是代码错了还是数据被修订了？

这些问题的共同特点是：**答错了不会报错**。因子照样算得出来，图照样能画，
只是数字是错的，而且没有任何环节会发现。

平台把这些判断点全部显式化：**能确定的自动做，不能确定的停下来问，
永远不猜。**

## 二、功能清单

### 2.1 从想法到因子（P0 主流程）

| 功能 | 说明 |
|---|---|
| 自然语言解析 | 一句研究想法 → 结构化的因子定义（`FactorSpec`） |
| 歧义识别与阻塞 | 「盈利质量」这类多口径表述会**停下流程**并给出候选，不替你选 |
| 规范公式渲染 | 模型只产出 AST，后端确定性渲染出你确认的那条公式 |
| 字段发现 | 7,478 个 Wind 字段的中文检索，含含义、单位、时间角色 |
| 字段验证 | Schema 验证（字段是否存在）与数据存在性验证（是否有数据）**分开** |
| 取数规划 | 自动补齐历史指数成分、预热区间、ST/停牌过滤 |
| 签名 manifest | 平台实际执行的唯一对象，可验签、可复现 |
| 隔离执行 | 无密钥 Worker，`network_mode: none` |
| 三层校验 | 数据层、公式层、结果层，分别报告阻塞项与提示项 |
| 代码导出 | 可读的 `factor.py`，供你在自己的环境复现 |

### 2.2 研报入口

| 功能 | 说明 |
|---|---|
| PDF 解析 | 文本型中英文研报，保留页码与坐标作为证据 |
| 受限 OCR | 仅对无文本层的页面运行，200 DPI，每份研报上限 50 页 |
| 因子抽取 | 从研报中提取因子定义，每条结论必须引用页内证据 |
| 人工确认闸门 | 置信度不足或版式不可靠时**强制人工确认**，不进入执行 |

### 2.3 因子检验与资产管理

| 功能 | 说明 |
|---|---|
| IC / Rank IC | 含离散度，不只报均值 |
| 分位收益与多空价差 | 单调性作为事实报告，不作为判断 |
| 换手率 | 按成分变动计算，不是权重漂移 |
| 因子库 | 不可变版本，工件复制入库而非引用 |
| 复现记录 | 记录取数时刻、数据快照与 9 个组件版本 |
| 多因子合成 | 方向统一 → 标准化 → 加权，顺序固定 |
| 指数权重 | Top N、等权或因子加权、周度/月度调仓、CSV 导出 |

### 2.4 治理与安全

| 功能 | 说明 |
|---|---|
| 口径注册表 | 单一 YAML，三值复核状态，非程序员可读可签字 |
| 三值闸门 | `unreviewed` 可试算但标注；`reviewed` 可发布；`disputed` **禁止执行** |
| 数据出境边界 B4 | Wind 原始数据、密钥、研报全文默认不外发 |
| 全本地模式 | `LOCAL_ONLY_MODE=true` 时禁止一切外部模型调用 |
| 两角色权限 | `admin` 管用户与口径复核，`researcher` 建因子 |

## 三、安装

需要 [uv](https://docs.astral.sh/uv/)（Python 3.11）与 Node 22+。

```bash
git clone https://github.com/zus12873/llm-factor-platform.git
cd llm-factor-platform

uv sync --project backend
npm --prefix frontend install
```

验证安装：

```bash
uv run --project backend pytest backend/tests -q      # 应为 634 passed, 12 skipped
npm --prefix frontend test -- --run                   # 应为 28 passed
```

这两条**不需要任何凭据**。

## 四、命令行操作流程

### 4.1 看看平台会做什么（最快的上手方式）

```bash
# 列出 37 个内置案例
uv run --project backend factor-platform list-cases

# 跑一个清晰的案例，看它走完整条链
uv run --project backend factor-platform run-case momentum_20d
```

输出：

```
parse    : rank(rolling_return(close, window=20))
clarify  : no blocking question
plan     : 4 步 — wind.index_components, wind.is_st_stock,
                  wind.is_suspended, wind.get_price
           预热区间自 2022-11-25 起
fetch    : 跳过（--real-wind 未给出；这是唯一需要凭据的阶段）
```

**注意「预热区间自 2022-11-25 起」**：请求的区间是 2024-01-01 开始，
但 20 日动量在第 1 天没有值，规划器自动往前多取了历史。你没要求，
但少了它前 20 天全是 NaN。

### 4.2 看看它拒绝做什么

```bash
uv run --project backend factor-platform run-case profitability_ambiguous
```

```
parse    : rank(profitability)
clarify  : blocked on profitability_definition
           （想法不够明确，按设计在此停下）
```

「盈利质量」有至少三种口径。平台不选，它问。

### 4.3 跑验收套件

```bash
uv run --project backend factor-platform run-case-suite --set golden \
  --report /tmp/golden.json
```

报告分组给出指标，并**明确列出无法测量的部分及原因** —— 不会用 0 或 1
假装测过。

### 4.4 构建 Wind 字段目录（需要 Wind 数据字典）

Wind 数据字典受商业授权保护，不随仓库分发。若你有授权：

```bash
# 1. 把字段索引放到 windquery/windquery/references/wind_field_index.md
uv run --project backend factor-platform build-wind-catalog \
  --source windquery/windquery/references/wind_field_index.md \
  --output backend/data/generated/wind_fields.jsonl

# 2. 解析数据字典，合并出字段元数据（中文名、单位、频率、市场）
uv run --project backend factor-platform sync-wds-metadata \
  --source "windquery/windquery/references/wind字典" \
  --index backend/data/generated/wind_fields.jsonl \
  --units backend/data/wind_field_units.yaml \
  --output backend/data/generated/wind_metadata.jsonl
```

第二条会如实报告覆盖率：

```
wrote 7478 fields to backend/data/generated/wind_metadata.jsonl
  described by dictionary : 7000 (93.6%)
  no metadata recovered   : 478 (kept and flagged, not dropped)
```

478 个字段没有元数据 —— 它们**仍然可检索**，只是排序时没有中文描述可用。
标注为「无元数据」而不是被丢掉。

### 4.5 验证一个字段（**需要 Wind 凭据**）

```bash
uv run --project backend factor-platform verify-field \
  ashareeodprices s_dq_close --shape point_range
```

两段独立报告：

```
schema: schema_valid_data_present — column exists with a compatible time role
sample: schema_valid_data_present — 60/60 sampled rows are non-null
  plan  : 3 securities × 20 trading_day
```

**「字段不存在」和「区间内无数据」是两件事。** 后者不阻塞 —— 字段可能完全有效，
只是你选的区间没有数据，那是你的判断不是平台的。

## 五、Web 界面操作流程

### 5.1 启动

```bash
# 终端 1：后端
APP_ENV=test uv run --project backend uvicorn --factory \
  factor_platform.main:create_app --host 127.0.0.1 --port 8000

# 终端 2：前端
npm --prefix frontend run dev
```

打开 http://localhost:5173

### 5.2 读懂顶部横幅

右上角始终显示组件状态：

| 显示 | 含义 |
|---|---|
| 🟢 全部就绪 | Wind 与模型均已配置 |
| 🟠 离线模式：wind、llm | **这两项未配置，结果基于替身数据** |
| 🔴 后端不可达 | 后端没起来或崩了 |

这不是装饰。看不到「离线模式」提示的话，你会把替身数据的运行读成真实运行。

### 5.3 完整操作流程

**第一步：填写研究想法**

上方四个结构化字段（资产类型、股票池、频率、区间）是**可信信封**——
模型不会改动它们。只有下方的自由文本会发给模型。

**第二步：处理澄清**

如果想法有多种口径，界面会弹出澄清卡片，列出候选并要求你选。
**没有「跳过」也没有「使用默认」**——这里的默认值就是整个设计要避免的那个猜测。

候选项来自口径注册表，已标记为 `disputed` 的口径不会出现在选项里。

**第三步：确认公式**

卡片主体是**正式公式**（由 AST 确定性渲染），下方是模型的自然语言说明，
带「仅供阅读，不参与执行」标签。

> 这两者的区分是刻意的：你确认的必须是会执行的那条，而不是它的解释。

**第四步：确认字段绑定**

表格逐列给出：变量、表、字段、含义、**单位**、时间角色、来源层。

**特别注意「单位」列。** 标注「单位未知」的字段，其量级错误在下游**不会被任何
检查发现** —— 市值按元而非万元读取是 10,000 倍误差，而结果看起来完全正常。

**第五步：查看计划与执行**

计划会列出全部步骤及预热区间。执行进入无密钥 Worker。

**第六步：读结果**

结果面板同时给出覆盖率与校验发现。校验发现按级别分组：

- **红色（阻塞）** —— 必须处理才能发布
- **黄色（提示）** —— 需要知道，但不阻止

如果因子引用了未复核口径，面板顶部会标「含未复核口径，不得作为正式发布」。

### 5.4 修订与级联失效

改公式、改字段、改区间都会触发**级联失效**：

| 你改了什么 | 什么会被清空 |
|---|---|
| 研究想法 | 全部下游，包括因子定义本身 |
| 公式 | 字段选择、计划、构建产物、结果 |
| 字段 | 计划、构建产物、结果 |
| 区间 / 股票池 | 计划、结果（构建产物保留） |
| 预处理 | 构建产物、结果（计划保留） |
| 时间口径 | 计划、构建产物、结果 |

分界线是：**改「取哪些行」失效计划，改「怎么算」失效构建产物。**

这不是为了麻烦你。没有级联失效的话，你改完公式后界面上仍挂着旧的字段选择和
旧的结果 —— 那个因子的各个部分**从未被一起计算过**，而数据里没有任何东西
表明这一点。

执行中的任务不接受修订，必须先取消 —— 否则会和 Worker 抢工件写入。

## 六、研报入口

### 6.1 上传

界面「研报提取」页支持拖拽 PDF。限制：50 MiB、200 页、非加密。

### 6.2 能力边界（界面上也会显示）

> 首期支持正文可复制、变量定义明确的中英文文本型研报。
> 图片公式、复杂数学排版与扫描版仅提取正文线索，公式需人工确认。

这不是免责声明，是设计决定。通用 OCR 会把数学记号弄坏成**仍能解析**的样子 ——
漏一个负号，因子方向就反了。所以 `formula_is_trustworthy("ocr")` 恒为 `False`。

### 6.3 抽取结果

三种情况：

| 状态 | 含义 | 你要做什么 |
|---|---|---|
| 已抽取（高置信度） | 公式识别可信 | 检查证据页码后继续 |
| 需人工确认 | 置信度不足、多栏版式或含图片 | **手动输入或修正公式** |
| 抽取失败 | 模型出错或无相关段落 | 依据仍给出的证据手动输入 |

**「进入因子工作流」按钮在公式未经确认前保持禁用。** 低置信度的抽取结果
在屏幕上看起来和好结果一模一样，按钮状态是唯一在执行这条规则的东西。

失败时仍然返回证据 —— 失败且不给证据，等于让你从零手工重来。

## 七、Worker 与队列运维

### 7.1 三条命令

```bash
export MANIFEST_SIGNING_KEY="<与后端相同的密钥>"

# 领一个任务跑完就退出
uv run --project backend factor-worker run-once \
  --job-root data/runtime/jobs \
  --artifact-root data/artifacts \
  --input-root data/artifacts/inputs

# 排空队列
uv run --project backend factor-worker serve --job-root ... --artifact-root ... --input-root ...

# 处理租约过期的任务
uv run --project backend factor-worker recover \
  --job-root data/runtime/jobs --artifact-root data/artifacts
```

### 7.2 Worker 持有什么

**只有 manifest 签名密钥，而且只用来验签。** 它没有数据库凭据、没有模型密钥。
被攻破的 Worker 什么也够不着。

### 7.3 recover 的三种处置

租约过期**不等于**该重跑：

| 情况 | 处置 |
|---|---|
| 结果完整（Parquet **与** result.json 都在） | 标记完成 |
| 无结果，未达重试上限 | 重新入队 |
| 无结果，已达上限（2 次） | 标记失败 |

Worker 可能在写完完整结果**之后**才死。盲目重跑会重复计算并覆盖你可能
已经打开过的工件。

| 变量 | 说明 |
|---|---|
| `WIND_ENABLED=true` | 打开真实取数 |
| `WIND_HOST` / `WIND_PORT` / `WIND_USER` / `WIND_PASSWORD` / `WIND_DATABASE` | Wind MySQL 只读副本 |

| `MANIFEST_SIGNING_KEY` | 同上，另生成一个 |
| `KIMI_CODING_BASE_URL` / `KIMI_CODING_API_KEY` | Coding Plan 端点（优先） |
| `KIMI_METERED_API_KEY` / `KIMI_MODEL` | 按量 API 兜底 |
| `LOCAL_ONLY_MODE=true` | 禁止一切外部模型调用 |

### 8.3 接入后的第一批验证

最新实测见 [`acceptance/2026-08-13/README.md`](acceptance/2026-08-13/README.md)。
优先三条：

```bash
# 1. 三种查询形态各验一个字段
factor-platform verify-field ashareeodprices s_dq_close --shape point_range
factor-platform verify-field asharefinancialindicator s_fa_roe --shape report_period
factor-platform verify-field aindexmembers s_con_indate --shape interval_overlap

# 2. 端到端真实取数
factor-platform run-case momentum_20d --real-wind

# 3. 单位核对（见下）
```

### 8.4 必须人工确认的口径

`backend/data/metric_definitions.yaml` 中 9 条口径全部标记 `review_status: unreviewed`。
需要**带教老师或资深研究员**逐条确认。优先三条 —— 它们各自都是量级或口径级的
静默错误来源：

| 口径 | 待确认 | 错了会怎样 |
|---|---|---|
| `ROE_TTM` | Wind 存的是百分数还是比值 | 差 100 倍 |
| `REVENUE_YOY` | 单季度同比还是累计同比 | 两个不同的因子 |
| `s_dq_volume` | 单位是股还是万股 | 换手率差 10,000 倍 |

确认后把 `review_status` 改为 `reviewed` 并填写 `reviewer` / `reviewed_at`。
在此之前，用这些口径算出的结果**可用于试算但不得作为正式发布**。

另有两条已登记为 `disputed`、平台直接拒绝，无需确认：
`FLOAT_MV`（`float_a_shr` 是股本不是市值）、
`CFO_WRONG_MAPPING`（现金流量表的 `net_profit` 是间接法起始行）。

## 十、常见问题

**点了「开始解析」没反应？**  
看顶部横幅。若显示「离线模式：llm」，说明模型未配置 —— 界面会给出
`llm_provider_unavailable` 错误码与处理建议。应用不会隐式调用 Fake Provider。

**为什么因子前 20 行全是 NaN？**  
20 日动量在窗口未满时**应该**没有值。用不足的历史凑出一个数，会让回测
前段悄悄变成另一个因子。这是正确行为。

**改了公式，字段选择怎么没了？**  
级联失效，见 [5.4](#54-修订与级联失效)。

**三个月后重跑，数字不一样了？**  
先看因子库里的复现记录。Wind 会**追溯修订财报** —— 同一份程序在不同时间
跑出不同结果，两次都是对的。`explains_difference_from()` 会告诉你是代码变了、
数据变了、还是口径变了。

**隐藏验收集在哪？**  
当前工作副本没有 `backend/data/hidden_cases/` 原始案例，只有历史验收报告。
不得从历史报告重建一套案例再声称是原隐藏集。

**能直接下单吗？**  
不能。指数产物只是调仓日权重，未计交易成本、冲击成本、涨跌停与停牌限制。
产物里自带这句声明。
