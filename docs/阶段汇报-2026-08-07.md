## 二、项目目标回顾

把研究员的一句话想法或一份卖方研报，自动变成一个**可执行、可复现、可审计**的量化因子。

```
自然语言研究想法 / 中英文卖方研报
    ↓
结构化 FactorSpec（因子定义）
    ↓
识别阻塞性歧义并向用户确认      ← 不猜，宁可问
    ↓
搜索并确认 Wind 字段
    ↓
匹配已有函数或受控通用查询
    ↓
确定性构建执行 manifest
    ↓
隔离执行（无密钥 Worker）
    ↓
数据、公式、结果三层校验
    ↓
保存、展示和检验因子
```

**首期范围**：日频 A 股、中小规模研究区间、线性多因子，**不含实盘交易**。  
**首要原则**：核心闭环的**正确性与安全性**第一，功能覆盖第二。

1. 解析成结构化的因子定义（因子名、假设、方向、公式 AST、所需变量）；

## 五、本阶段技术重点：一轮评审带来的架构修订

项目中途做了一轮技术评审，产出 **13 条问题，其中 9 条改变了架构或数据契约**。

**处理方式**：先停下来把契约改对，再继续写功能——而不是带着已知缺陷往下堆代码。这个决定推迟了约 1 天的功能进度，但避免了后续 Task 12/13（公式编译与执行）建立在错误契约上返工。

### 修订 1：公式只保留一个事实来源

**问题**：原设计中模型同时产出两个公式表示——`formula_text`（给人看的文本）和 `formula_ast`（给机器执行的语法树）。两者由模型分别生成，**必然会漂移**。一旦漂移，用户在界面上确认的公式和 Worker 实际执行的公式就不是同一个东西，而且这种错误不会报错，只会静默算出错的因子值。

**修订**：模型**只**产出 `formula_ast`。后端用确定性渲染器从 AST 生成 `canonical_formula`，这才是用户确认的正式公式。模型的自然语言描述降级为 `formula_explanation`，只用于展示，不参与任何判断。

**结果**：用户看到什么，机器就算什么，结构上不可能不一致。

### 修订 2：预处理从公式 AST 中拆出

**问题**：去极值（winsorize）、标准化（zscore）、行业中性化原本作为算子混在公式 AST 里。但这三者有**执行顺序语义**——先中性化再标准化，和先标准化再中性化，结果不同。AST 的树形结构表达不了「有序流水线」，而原设计用布尔开关控制，顺序被隐式写死在代码里。

**修订**：AST 算子从 14 个精简到 11 个，三个预处理算子移出。新增有序 `PreprocessingPipeline`，每一步带显式 `order`，并区分作用对象是**变量**还是**因子**。同时加了校验：同一操作不得在同一对象上重复，顺序号不得冲突。

### 修订 3：显式的时间口径契约（防未来函数）

**问题**：Point-in-time 正确性有两个半边。查询层保证了「不读还没公布的字段」——这是第一半。但第二半被漏掉了：**用 T 日收盘价算出的因子，在 T 日盘中是不可知的，不能在 T 日交易**。一条不读任何未来字段的数据管道，照样可以产生未来函数。原设计把这一点留给人记住，而人会忘。

**修订**：新增 `TimeConvention` 契约，把观测时点、信息可得时点、信号日、交易日、执行价、前向收益起止全部显式化，并在数据模型的校验器里强制约束：

- 若信息在收盘后才可得，最早交易日必须顺延至少一天，否则直接拒绝；
- 前向收益起始日不得早于交易日；
- 公告时点无法确定时，默认**保守顺延**至下一交易日。

默认口径：T 日收盘计算 → T 日形成信号 → T+1 日交易 → 次日开盘执行。

### 修订 4：Worker 不再执行大模型生成的代码

**问题**：原设计中大模型生成 Python 代码，Worker 用 AST 白名单校验后执行。这意味着**模型输出直接进入执行路径**，白名单一旦有疏漏就是任意代码执行。

**修订**：Worker 改为执行后端确定性构建的**签名 manifest**。生成的 `factor.py` 降级为给用户看的导出产物，不参与执行。源码 AST 白名单机制整体取消——因为不再需要。

### 其余修订

| 修订 | 说明 |
|---|---|
| 新增信任边界 B4 | Wind 原始数据、密钥、研报全文默认不得发送至外部模型服务；提供全本地模式 |
| 口径争议升级为阻塞 | `disputed` 状态从警告升级为阻塞，无绕过通道 |
| 字段发现扩为七层漏斗 | 专用函数 → 人工别名 → WDS 元数据 → BM25 → information_schema → 样本验证 → 用户确认 |
| Schema 验证与数据存在性验证分离 | 字段存在 ≠ 该区间有数据，两件事分开报告 |
| 任务队列补齐运维语义 | 租约、超时恢复、幂等键、取消、工件清理 |
| 修订事件与级联失效 | 用户改公式后必须使下游产物失效（进行中，见第八节） |
| 案例集扩至 30+ 并增设隐藏验收集 | 防止实现过拟合到已知的 10 个案例 |
